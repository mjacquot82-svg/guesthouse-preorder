# Render production deployment

This runbook deploys only the FastAPI backend. The React frontend remains at
`https://ladels.jdsstudio.ca`, and PostgreSQL remains in the existing Supabase
project.

## Render service

Create a Blueprint from this repository's root-level `render.yaml`, or create a
Web Service manually with these exact settings:

| Setting | Value |
|---|---|
| Service name | `guesthouse-preorder-api` |
| Runtime | `Python 3` |
| Python version | `3.12.13` |
| Branch | `main` |
| Region | The Render region closest to the existing Supabase project |
| Root/working directory | `backend` |
| Instance type | `Starter` or larger; do not use Free for production payments |
| Build command | `python -m pip install .` |
| Pre-deploy command | `alembic upgrade head` |
| Start command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Health check path | `/health/ready` |
| Auto-deploy | Off until the first production smoke test is complete |
| Custom domain | `api.ladels.jdsstudio.ca` |

The application entry point is `app.main:app`, relative to the `backend`
working directory. Render supplies `PORT`; do not create a fixed `PORT`
environment variable. Python 3.12.13 is pinned both by the Blueprint's
`PYTHON_VERSION` environment variable and by `backend/.python-version`, which
is inside the service root directory and therefore available during Render's
build.

The readiness endpoint executes `SELECT 1` against PostgreSQL. Render will not
route a deployment as healthy if the Supabase connection is unavailable.
`/health/live` checks only that the FastAPI process is running.

## Environment variables

Set these in Render. Values marked secret must be entered in the Render
Dashboard and must not be committed.

| Key | Exact value or source | Secret |
|---|---|---:|
| `PYTHON_VERSION` | `3.12.13` | No |
| `DATABASE_URL` | Supabase **Session pooler** connection string, adapted as described below | Yes |
| `FRONTEND_URL` | `https://ladels.jdsstudio.ca` | No |
| `PUBLIC_APP_URL` | `https://api.ladels.jdsstudio.ca` | No |
| `CLOVER_ENVIRONMENT` | `production` | No |
| `CLOVER_APP_ID` | Production Clover app ID | Yes |
| `CLOVER_APP_SECRET` | Production Clover app secret | Yes |
| `CLOVER_MERCHANT_ID` | Production merchant ID | Yes |
| `CLOVER_STATE_SECRET` | A unique random value of at least 32 characters | Yes |
| `CLOVER_WEBHOOK_SECRET` | Secret generated by Clover for the Hosted Checkout webhook | Yes |
| `CLOVER_TOKEN_ENCRYPTION_KEY` | A Fernet key | Yes |

Optional variables:

| Key | When to set |
|---|---|
| `CLOVER_PAGE_CONFIG_UUID` | Only when using a configured Clover Hosted Checkout page UUID |
| `CLOVER_ECOMMERCE_PRIVATE_TOKEN` | Only when intentionally using the pinned merchant's private Ecommerce token instead of OAuth |

Generate the application-owned secrets locally:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Use the first command for `CLOVER_STATE_SECRET`. Never reuse it as
`CLOVER_WEBHOOK_SECRET`.

## Supabase connection

In Supabase, open **Project > Connect** and copy the **Session pooler**
connection string. Session mode uses the shared Supavisor hostname and port
`5432` and is appropriate for a persistent SQLAlchemy service connecting over
IPv4.

Change only the URL scheme so SQLAlchemy selects the installed psycopg 3
driver:

```text
postgresql+psycopg://postgres.PROJECT_REF:PASSWORD@aws-REGION.pooler.supabase.com:5432/postgres?sslmode=require
```

Use the exact username, password, hostname, and database shown by Supabase.
Percent-encode URL-significant password characters. Do not use the transaction
pooler on port `6543` for this service, and retain `sslmode=require` so the
public database connection cannot fall back to plaintext. The direct
`db.PROJECT_REF.supabase.co:5432` URL is also suitable only when the Supabase
project has IPv4 connectivity enabled and Render can reach it.

Before the first deploy, confirm that the existing database is the intended
production database and has a backup. The pre-deploy command applies every
pending migration through revision `20260729_04`.

## DNS

First add `api.ladels.jdsstudio.ca` under the Render service's **Settings >
Custom Domains**. Render will show the service's assigned hostname.

At the authoritative DNS provider for `jdsstudio.ca`, create:

| Type | Name/host | Target/value | TTL |
|---|---|---|---|
| `CNAME` | `api.ladels` | `guesthouse-preorder-api.onrender.com` | `300` seconds or provider default |

If `ladels.jdsstudio.ca` is delegated as its own DNS zone, enter `api` as the
name/host instead of `api.ladels`; the resulting fully qualified record must
still be `api.ladels.jdsstudio.ca`.

If Render assigns a suffixed hostname because the requested service name is
unavailable, use the exact `*.onrender.com` hostname shown in the Render
Dashboard instead. Remove any existing `A`, `AAAA`, or `CNAME` record for
`api.ladels` before adding this record. If the DNS provider is Cloudflare, use
DNS-only mode until Render verifies the domain and issues TLS.

Do not add an `A` record for this subdomain. After DNS propagates, click
**Verify** in Render and wait for the managed certificate.

## Clover production values

After `https://api.ladels.jdsstudio.ca/health/ready` returns HTTP 200, enter:

| Clover field | Exact value |
|---|---|
| Site URL | `https://api.ladels.jdsstudio.ca/api/v1/clover` |
| Alternate Launch Path | `/api/v1/clover/oauth/start` |
| CORS Domain | Leave blank |
| Default OAuth Response | `Code` |
| OAuth redirect/callback URL | `https://api.ladels.jdsstudio.ca/api/v1/clover/oauth/callback` |
| Hosted Checkout webhook URL | `https://api.ladels.jdsstudio.ca/api/v1/clover/webhooks/hosted-checkout` |

Set Hosted Checkout success, failure, and cancellation redirects dynamically;
the backend already supplies URLs under:

```text
https://ladels.jdsstudio.ca/confirmation
```

Generate the webhook signing secret in Clover, copy it immediately into
Render as `CLOVER_WEBHOOK_SECRET`, and restart/redeploy the service before
accepting checkout traffic. Then open:

```text
https://api.ladels.jdsstudio.ca/api/v1/clover/oauth/start
```

Complete OAuth while signed in to the pinned production merchant.

## Manual deployment checklist

1. Confirm the Supabase project region and choose the closest Render region.
2. Back up the existing Supabase production database.
3. Copy the Supabase Session pooler URL and convert its scheme to
   `postgresql+psycopg://`.
4. Generate independent OAuth-state and Fernet encryption secrets.
5. In Render, create a Blueprint from the repository and review
   `render.yaml`; do not create a Render database.
6. Enter every secret environment variable requested by the Blueprint.
7. Keep automatic deploys disabled and start the first deployment manually.
8. Confirm the build completes and `alembic upgrade head` reaches revision
   `20260729_04`.
9. Confirm the service starts with `app.main:app` and binds Render's `PORT`.
10. Test `/health/live`; expect HTTP 200 with `"status": "ok"`.
11. Test `/health/ready`; expect HTTP 200 with `"database": "ok"`.
12. Add the Render custom domain and the DNS CNAME described above.
13. Wait for DNS verification and Render-managed TLS.
14. Re-test both health endpoints through
    `https://api.ladels.jdsstudio.ca`.
15. Set Netlify's production `VITE_API_BASE_URL` to
    `https://api.ladels.jdsstudio.ca` and redeploy the frontend.
16. Configure the exact Clover URLs above in the production Clover app.
17. Generate the Hosted Checkout webhook secret, replace the temporary Render
    value, and restart/redeploy the backend.
18. Complete production Clover OAuth for the configured merchant.
19. Perform one controlled preorder and verify the signed webhook changes the
    order to `paid`.
20. Enable Render automatic deploys only after the production smoke test and
    application-level admin authentication are complete.
