# Clover integration setup

## Dashboard values

This application uses a trusted FastAPI server for OAuth and Hosted Checkout.
The production API origin is `https://api.ladels.jdsstudio.ca`.

Enter these values in **Clover Developer Dashboard > App Settings > REST
Configuration**:

| Field | Value |
|---|---|
| Site URL | `https://api.ladels.jdsstudio.ca/api/v1/clover` |
| Alternate Launch Path | `/api/v1/clover/oauth/start` |
| CORS Domain | Leave blank |
| Default OAuth Response | `Code` |

The exact OAuth redirect URI generated by the application is:

`https://api.ladels.jdsstudio.ca/api/v1/clover/oauth/callback`

The redirect URI is a subpath of the Site URL and uses the same scheme and
hostname. Do not enter the Netlify storefront URL in the CORS field: the
browser never calls Clover's REST API directly.

The production frontend origin is `https://ladels.jdsstudio.ca`. Deploy and
verify the FastAPI service and custom-domain TLS before completing OAuth.

## Clover app settings

1. Set App Type to **Web** under **REST Clients**.
2. In Requested Permissions, enable only the REST permissions used by the
   merchant/catalog/order synchronization work. Permission changes require the
   test merchant to uninstall and reinstall the app.
3. Enable **Online payments** in the Ecommerce permission section.
4. Set Ecommerce Settings to **Hosted Checkout**.
5. Keep the OAuth response type set to **Code**. The app secret and token
   exchange belong on the backend.
6. Install/connect the app to the sandbox test merchant, then launch:
   `https://api.ladels.jdsstudio.ca/api/v1/clover/oauth/start`.

Set `CLOVER_MERCHANT_ID` to the one merchant this storefront is allowed to
charge. OAuth callbacks for any other merchant are rejected. Clover also
supports a merchant-generated Hosted Checkout private token; set
`CLOVER_ECOMMERCE_PRIVATE_TOKEN` to use it for the pinned merchant. If it is
absent, checkout uses that merchant's OAuth token and automatically refreshes
its expiring access token.

## Backend environment

Required:

```dotenv
DATABASE_URL=postgresql+psycopg://...
FRONTEND_URL=https://ladels.jdsstudio.ca
PUBLIC_APP_URL=https://api.ladels.jdsstudio.ca
CLOVER_ENVIRONMENT=sandbox
CLOVER_APP_ID=...
CLOVER_APP_SECRET=...
CLOVER_MERCHANT_ID=...
CLOVER_STATE_SECRET=...
CLOVER_WEBHOOK_SECRET=...
CLOVER_TOKEN_ENCRYPTION_KEY=...
```

Optional:

```dotenv
CLOVER_PAGE_CONFIG_UUID=...
CLOVER_ECOMMERCE_PRIVATE_TOKEN=...
```

Generate the two local security values:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Use different values for the OAuth state secret and Clover-generated webhook
secret. The backend rejects short secrets, malformed Fernet keys, unexpected
merchant IDs, and public URL values containing paths, credentials, queries, or
fragments.

Run the database migration before connecting Clover:

```bash
cd backend
alembic upgrade head
```

## Frontend environment

Build Vite with the deployed FastAPI origin:

```dotenv
VITE_API_BASE_URL=https://api.ladels.jdsstudio.ca
```

FastAPI permits browser API requests only from the exact `FRONTEND_URL` origin
and does not enable cross-origin credentials. Localhost is not automatically
allowed in production. Do not include a trailing slash in either public origin
value.

## Implemented URLs

| URL | Purpose |
|---|---|
| `GET /api/v1/clover` | Clover app launch entry |
| `GET /api/v1/clover/oauth/start` | Signs state and redirects to Clover v2 OAuth |
| `GET /api/v1/clover/oauth/callback` | Exchanges the code and stores encrypted tokens |
| `GET /api/v1/clover/connection` | Admin connection status |
| `POST /api/v1/clover/orders/{public_token}/checkout` | Creates/reuses a 15-minute Hosted Checkout session |
| `POST /api/v1/clover/webhooks/hosted-checkout` | Verifies Clover's HMAC signature and records payment state |

Hosted Checkout success, failure, and cancellation return to:

`https://ladels.jdsstudio.ca/confirmation?order={PUBLIC_ORDER_TOKEN}&payment={RESULT}`

The checkout request includes Clover's checkout-session placeholder for the
success and failure result URLs.

In the test merchant dashboard, go to **Settings > View all settings >
Ecommerce > Hosted Checkout** and set:

| Hosted Checkout field | Value |
|---|---|
| Webhook URL | `https://api.ladels.jdsstudio.ca/api/v1/clover/webhooks/hosted-checkout` |
| Success redirect | Supplied dynamically by the checkout request |
| Failure redirect | Supplied dynamically by the checkout request |
| Cancellation redirect | Supplied dynamically by the checkout request |

Click **Generate** beside the webhook URL and store the resulting signing
secret as `CLOVER_WEBHOOK_SECRET`. A browser redirect is never treated as proof
of payment; only a correctly signed `PAYMENT` webhook changes an order to
`paid` or `payment_failed`.

Checkout currently requires `tax_cents` to be zero. Clover Hosted Checkout does
not automatically apply the merchant's default tax configuration, so the
backend rejects a non-zero local tax instead of undercharging or representing
tax as a merchandise line. Configure and test Clover tax rates before enabling
non-zero application tax.

## Production switch

After sandbox verification:

1. Configure the same URLs in the production side of the Global Developer
   Dashboard.
2. Set `CLOVER_ENVIRONMENT=production`.
3. Use the production App ID and App Secret.
4. Reconnect the production merchant; sandbox tokens cannot be reused.

North American production calls use `www.clover.com` for authorization and
`api.clover.com` for token, refresh, and Hosted Checkout requests.
